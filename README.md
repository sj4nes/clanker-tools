# clanker-tools

![A robot in a spacecraft lab holding a device labelled "PURPOSE DEVICE" projecting a holographic terrain scan](docs/assets/purpose-device.png)

A catalog of agent skills, compatible with both **Hermes** and **Claude Code**.

## Layout

```
skills/<name>/
  SKILL.md          top-level, YAML frontmatter + instruction body
  references/        linked docs, deep-dive material
  templates/         boilerplate the skill emits (optional)
templates/
  skill-template/    starting point for a new skill
.claude/skills/      symlinks into skills/ so Claude Code discovers them
```

## Skill rules

- Every skill has a top-level `SKILL.md` with valid YAML frontmatter: `name`,
  `description` (required); `version`, `author`, `tags` (optional).
- Each skill is self-contained in its own directory under `skills/`.
- Linked docs go in `references/`; boilerplate goes in `templates/`.
- **Truncation gate:** each `SKILL.md` is capped at 20,000 characters. If a
  skill outgrows that, split it or move depth into `references/`.
- No secrets or runtime state in skill files — skills are procedural memory,
  not config.

## Skills

Each skill packages a disciplined workflow — how an agent should use a tool or
method carefully, what it must never be used for, and how to verify the result.
They all follow the same shape: a `SKILL.md` with the core doctrine and
`references/` holding the deep-dive material. The catalog is grouped by domain
below — skip to the section that interests you.

- [Command-line tools](#command-line-tools) — disciplined use of one Unix tool each

### Modelling and analysis methodology

| Skill | Purpose |
|---|---|
| [`simulation`](skills/simulation/SKILL.md) | A disciplined modeling-and-evidence workflow for building a surrogate model to answer a decision question about a real or hypothetical system: frame the decision, write a model charter, pick the paradigm (continuous / discrete-event / agent-based / system-dynamics / Monte Carlo / PDE / network / state-machine / hybrid / surrogate), formalize before coding, implement reproducibly, verify, validate to the intended use, quantify uncertainty and sensitivity, design the experiment, and report a decision with its limits. Refuses when there is no decision question, no output metric, a single run of a stochastic system, or a prediction outside the validated domain. Paradigm mechanics, V&V / UQ / calibration, analog-digital-hybrid and co-simulation, and charter / experiment / reporting templates with a worked discrete-event example in [`references/`](skills/simulation/references/). |
| [`design-of-experiments`](skills/design-of-experiments/SKILL.md) | Turning a vague causal or optimization question into a defensible experiment: charter first (decision, owner, experimental unit, estimand, minimum practical effect), then objective + evidence classification, causal-structure map, least-complex-adequate design (completely randomized / block / cluster / crossover / factorial / fractional factorial / response surface / stepped-wedge / switchback / adaptive / simulation), power- or precision-based sample size with every required adjustment (design effect, multiplicity, attrition, autocorrelation), a pre-registered analysis plan, an instrumentation and sample-ratio-mismatch audit, risk tiering and governance, and a decision report that states the effect with its uncertainty and the conditions that reverse it. Never proposes a fractional factorial without its alias structure; refuses pseudoreplication, post-hoc plan changes, and causal claims on unrandomized assignment. Objective/evidence/design catalogue, factorial + screening + RSM, power formulas, analysis-plan model selection, execution integrity, ethics, and a simulation-DOE mode in [`references/`](skills/design-of-experiments/references/); charter / analysis-plan / decision-report skeletons in [`templates/`](skills/design-of-experiments/templates/). |
| [`visualization-design`](skills/visualization-design/SKILL.md) | Turning an audience, a message, and data or structure into the simplest visual artifact that lets that audience accurately perceive, compare, question, and act — then auditing and critiquing it. Write the visual brief; classify the **visual job** (comparison / trend / distribution / relationship / composition / ranking / uncertainty / process / hierarchy / network / spatial / causal / architecture / sequence / tradeoff / dynamic) before the chart type; specify encodings on perceptually accurate channels (Cleveland–McGill); run the graphical-integrity audit (proportional encoding, zero baselines, disclosed transforms, visible evidence status and uncertainty, no implied causation); build the accessibility package (no meaning by colour alone, contrast, grayscale/CVD, alt text, data table); emit diagram-as-code / chart-as-code with provenance; and score against a critique rubric with an automated red-flag list. Refuses truncated-baseline / 3D / area-for-length distortion, unlabelled uncertainty bands, forecasts drawn like observations, colour-only status, ambiguous diagram arrows, and causal claims on associational data. Visual-selection chooser, integrity audit, perception + Tufte + colour + hierarchy, accessibility protocol, diagram grammar, simulation/DOE/causal/architecture modes, and the critique engine in [`references/`](skills/visualization-design/references/); brief / spec / critique-report skeletons in [`templates/`](skills/visualization-design/templates/). |
| [`control-systems`](skills/control-systems/SKILL.md) | Turning a system, an objective, and a constraint set into a feedback controller that stays stable, safe, performant, and robust under disturbance, uncertainty, actuator and sensor limits, and real-time constraints — then verifying it and staging its deployment. Frame the problem and gate on safety (risk class: advisory / low-risk / supervised / high-consequence / prohibited); build or identify the model with its operating regime and uncertainty envelope; check controllability / observability against the actuator, delay, bandwidth, and noise reality; choose the architecture (feedback / feedforward / cascade / supervisory / MPC / hybrid + independent safety filter and human override) before tuning; design the controller (on-off / PID with anti-windup / loop shaping / pole placement / LQR / LQG / MPC / robust / adaptive / nonlinear / gated learning) with nominal stability and robustness-margin evidence; run a fault / disturbance / mismatch / override / cyber scenario matrix; and report against the simulation → SIL → HIL → shadow → pilot ladder. Refuses autonomous actuation for high-consequence systems without an assurance plan and independent protection, "robust" without a declared envelope, single-run judgement of an uncertain plant, simulation presented as a safety argument, and any design that bypasses a safety filter or human override for a metric. Modelling, controller catalogue, robust/adaptive/nonlinear/learning, architecture and timing, safety/security/humans, and V&V/deployment in [`references/`](skills/control-systems/references/); charter / controller-spec / assurance-report skeletons in [`templates/`](skills/control-systems/templates/). |
| [`unknown-discovery`](skills/unknown-discovery/SKILL.md) | Turning a decision or system into a repeatable discovery process that expands the search space, surfaces hidden assumptions, generates competing explanations, scans for weak signals and anomalies, and converts uncertainty into safe prioritized learning. Scope and gate on decision relevance; build the epistemic map (known known / known unknown / unknown known / ambiguity / measurement blind spot / model-form / deep uncertainty / tail risk / unknown-unknown candidate areas); mine and rank assumptions (`P = I·U·(1−R)·D`, components kept) with a mandatory disconfirming signal and earliest indicator per entry; generate alternatives (Key Assumptions Check, premortem across twelve lenses, red-team modes, outside view, stakeholder inversion, boundary challenge, analysis of competing hypotheses with a diagnosticity-weighted evidence matrix); search for surprise (horizon-scan signal cards, residual/anomaly analysis, near-misses, blameless surprise review); rank the learning backlog by value of information and prefer bounded reversible probes; keep a Brier-scored forecast ledger with a bucketed calibration review; and set a monitoring plan with indicators, thresholds, escalation, and a reassessment cadence. Refuses a brainstorm presented as validated analysis, a point probability on a deep uncertainty, an assumption with no disconfirming signal, a cheap probe treated as confirmation, contradictory evidence dismissed as "noise", and any claim that running the process means every unknown has been found. Taxonomy + assumption mining, challenge methods + ACH, signals + surprise, probes + value of information, forecasting + calibration, and governance + failure modes in [`references/`](skills/unknown-discovery/references/); charter / assumption-register / discovery-report skeletons in [`templates/`](skills/unknown-discovery/templates/). |

## Adding a skill

1. `cp -r templates/skill-template skills/<name>`
2. Fill in `SKILL.md` frontmatter and body; add `references/` as needed.
3. `ln -s ../../skills/<name> .claude/skills/<name>` for Claude Code discovery.
4. Add a row to the matching domain table under [Skills](#skills).
