# term_syntax

## Type
definition  (epistemic status: `definition`; `constructive_grade: intuitionistic`)

## Statement
The **terms** of a signature `ℒ` are generated by the `inductive_definition`:
- every **variable** `x` is a term;
- every **constant symbol** `c ∈ ℒ` is a term;
- if `f ∈ ℒ` is an `n`-ary function symbol and `t₁, …, tₙ` are terms, then
  `f t₁ … tₙ` (or `f(t₁, …, tₙ)`) is a term.

A **closed term** (ground term) has no variables.

## Symbols
- `t, u`: terms; `var(t)`: the (finite) set of variables in `t`.

## Prerequisites (tsort edges into this node)
`signature`, `inductive_definition`.

## Content
Terms denote **elements of the domain** (via `term_evaluation`); they never
carry truth values (that is `atomic_formula`). Terms are uniquely readable
(analogue of `wff_unique_readability`), so **recursion on term structure** is
well-defined — used by `term_evaluation`, `substitution`, and the
`term_model` construction.

## Constructive grade
`intuitionistic` — a decidable inductive type; parsing and `var(·)` are
computable.

## Lean status
`lean_status: cited`. Mathlib's `FirstOrder.Language.Term` is exactly this
inductive type (`var` / `func`). Not in `validation/proof-checks.lean`
(propositional).

## Type / well-formedness check
`well_formed`. `f` must be applied to **exactly** its arity many terms; the
result is a term, **not** a formula. Unique readability holds (prefix/Polish-style
or fully parenthesised). `var(t)` is finite (`≤` term length).

## Specialization / boundary cases
- **relational signature** (no function symbols): the only terms are variables
  and constants.
- **closed terms**: form the domain of the `term_model` (modulo provable
  equality); `∃` witnesses in `henkin_theory` are closed terms.
- `ℒ_arith`: `S(S(0))`, `x + S(0)`, `x · y` are terms; `0 < S(0)` is **not** a
  term (it is a formula).
- term **depth** / **size**: a `formula_complexity`-style measure for term
  recursion.

## Hypothesis-dropped counterexamples
- **arity mismatch**: `f(t)` for binary `f` is not a term.
- **relation symbol as a function**: `R(t₁, t₂)` is an `atomic_formula`, not a
  term — using it inside another term (`f(R(t₁,t₂))`) is ill-formed.
- **quantifier inside a term**: there is no such thing — quantifiers bind in
  formulas only.

## Common misuse
Treating an atomic formula (`R t₁ t₂`, `t₁ = t₂`) as a term; arity errors;
putting a connective or quantifier in a term; forgetting closed terms are what
the term model is built from.

## Related nodes (non-prerequisite)
- `built_from`: `signature`.
- `feeds`: `atomic_formula`, `substitution`, `term_evaluation`, `term_model`.
- `analogue`: `wff_syntax` (unique readability, structural recursion).
