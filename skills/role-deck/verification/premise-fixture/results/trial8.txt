The marker is passed as a regular expression, not a literal string. On this machine grep resolves to ugrep, which rejects it outright: ugrep: error: error at position 4, (?m)*** FAIL, empty (sub)expression. grep therefore exits 2 (usage error), never 0. The marker-detection check is dead code. set -e does not help. Confirmed empirically: grep -q '*** FAIL' gives exit 2; grep -qF '*** FAIL' gives exit 0 on the same input. Fix: grep -qF '*** FAIL'.
