# Verification — `formula-tree-tutorial`

## What verification means for this skill

This skill produces **documents**, so the claim under test is structural: a
tutorial generated by this workflow carries a fixed set of beats, and a reader
browsing `<capsule>/tutorial/` can tell from the file what it is for. That is
checkable against every tutorial the repository has actually shipped, which is
what this harness does.

It does **not** check that a tutorial is good, correct, or well paced. What it
checks is that the parts the skill prescribes are present — and, in step 2,
that each of those checks is capable of reporting their absence.

## Case

**All 24 tutorials in `skills/*/tutorial/`** — 7 electrochemistry, 7 chemistry
foundations, 5 math, 5 physics. The corpus is the case: the skill's output is
the only evidence about the skill, and 24 documents built by different hands
over three weeks is a better subject than one fixture written to pass.

The mutation subject is
`chemistry-foundations/tutorial/solving-an-equilibrium.md`, chosen because it
carries every beat, so each mutant removes exactly one.

## Run

    sh skills/formula-tree-tutorial/verification/run.sh

It checks tutorials from **both** tutorial skills, because both implement
[`docs/capsule-tutorial-contract.md`](../../../docs/capsule-tutorial-contract.md).
The harness lives here rather than being duplicated — duplicating it is the
mistake the contract exists to undo.

`python3` (stdlib only, no `bc` arithmetic in this skill). Wall time < 2 s.
`upmd` is **not** invoked here — that each tutorial's blocks execute is checked
by workflow step 7 at authoring time, per tutorial; this harness is about the
document's shape.

## Findings folded back into the skill

1. **The skeleton had no lead paragraph, and 19 of 24 authors added one
   anyway.** The 5 without (`pendulum`, `why-heat-engines-have-a-ceiling`,
   `how-fast-does-sound-travel`, `designing-an-organ-pipe`,
   `horns-and-reciprocity`) were the ones that followed
   `references/document-structure.md` *exactly*. Nineteen independent
   departures from a skeleton is the skeleton being wrong, so the beat was
   added to the skeleton — and a "The lead" section written under it — rather
   than the five files being treated as defective. They were then given leads.
2. **`hole-in-the-rationals` was missing `## Where to go next`**, found by this
   check's first run. Added, pointing at `heine_borel` → IVT/EVT → the integral
   chain.
3. **Two defects in this harness, both found by step 2 and neither by step 1.**
   The capstone guard matched only headings *starting* with "Capstone", so it
   called `hole-in-the-rationals` capstone-less when its heading reads
   `## 12. Capstone — the verdict`. And `^#\s+` matched **shell comments inside
   fenced code blocks**, so a tutorial with its title deleted still reported a
   title; the same flaw would have counted a commented `##` as a section.
   Fixed by masking fence interiors before any structural match. Recorded here
   because step 1 passed 24/24 both before and after that fix: **the corpus
   check could not see its own blind spot, and the mutation check could.**

4. **The skeleton was maintained in two copies, and had drifted in both
   directions.** Measured 2026-09-22 across both tutorial skills: 8/8 workflow
   steps identical by name and order, 4/4 SKILL.md sections identical, 3/3
   reference filenames identical — on 22.5% literal text overlap. The lead was
   in the math skeleton only (causing finding 1); the Lean beat is prescribed in
   the math skill only, yet physics and chemistry tutorials carry **23 `lean_`
   blocks to mathematics' 16**. Resolved by single-sourcing the shared parts as
   [`docs/capsule-tutorial-contract.md`](../../../docs/capsule-tutorial-contract.md),
   thinning both skeletons to their domain deltas, and backporting the `cx_` and
   `lean_` beats into this skill's step 5. `check_contract.py` is the guard.
5. **`check_contract.py` caught a leftover on its first run** — the
   `## The lead` section this skill had gained hours earlier survived the
   thinning, because it sat after the Static Artifact section. Exactly the
   second-copy failure it was written for, found within a minute of existing.

No correctness fix was needed in `SKILL.md`'s workflow steps themselves; the
changes are to `references/document-structure.md` and the shared contract.

## The displacement table (§7)

`formula-tree-tutorial` is a **meta/behaviour** skill: it displaces how an agent
would otherwise turn a capsule into a lesson.

| Section | Default displaced | Where that default visibly fails |
|---|---|---|
| Workflow 2 "Extract the ordered node list" | Teaching in the order the topic is usually taught | A tutorial that uses a formula before the section that derives it; `tsort` order makes the dependency the outline |
| Workflow 5 "Convert each capsule check into a named block" | Prose that *states* the result | The reader cannot tell a correct formula from a typo; a named block makes them run it |
| Workflow 7 "Verify it runs" | "The examples look right" | A missing `deps:` — the block passes in a full run and fails standalone |
| `document-structure.md` "The lead" | Opening with install instructions | Identical in all 24 files, so a reader browsing a directory cannot choose between them (this run) |
| Workflow 6 "Add a capstone" | Ending at the last node | The chain is never spent on one real question end to end |
| Workflow 3 "one section per node" (`judgement`) | Sections sized by how much there is to say | No harness can tell over-long prose from necessary prose |
| `authoring-from-nodes.md` "choosing which check to surface" (`judgement`) | Surfacing whichever check exists | Which check *teaches* is an authorial call |
| Workflow 1 "Choose the tutorial's scope" (`judgement`) | Covering the whole capsule | Scope is a reader decision, not a graph property |

**5 covered · 3 judgement · 0 gaps**

## The gates are necessary, not sufficient

The harness reads shape. It cannot tell whether a lead is *accurate* about the
tutorial beneath it — a lead promising the Carnot ceiling on a document about
organ pipes passes every check here. It cannot judge pacing, whether the right
check was surfaced, or whether the physics is taught well. It does not run the
blocks: `upmd --ci --all` remains workflow step 7's job, per tutorial, at
authoring time. And it checks only tutorials that exist in this repository — it
says nothing about one an agent is about to write, which is why the beat also
went into the contract where an author will read it.

`check_contract.py` checks that both skills *point at* the contract and do not
re-declare its sections. It cannot tell whether a skill's domain delta
**contradicts** the contract — a skill could describe a different block
vocabulary in its own words and pass. What stops that is that the beats
themselves are checked, in step 1, against the tutorials both skills produce.
